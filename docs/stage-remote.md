# 服务器本机播放与多人遥控（Stage Remote）

本 Fork 新增的核心场景：在一台服务器（或常开的电脑）上用浏览器当「播放器」出声，小群里的其他人用手机或电脑打开同一个网址遥控它——搜歌、点歌、切歌、管队列，音乐从服务器所在的音响里放出来。

> 适合朋友、家人、小团队内部使用。令牌鉴权能挡住误入的访问者，但这不是面向公网陌生人的多租户系统，请放在可信网络或带访问控制的反向代理之后。

## 角色

| 角色 | 打开方式 | 作用 |
| --- | --- | --- |
| **Host** | `http://服务器:3000/?host=1&token=令牌` | 真正播放声音的页面，要常开。显示本机账号、本地曲库。 |
| **遥控端** | `http://服务器:3000/?token=令牌` | 带令牌的地址默认进入遥控模式，镜像 Host 的播放状态与队列。 |
| **本机播放** | 不带令牌直接打开，或在设置里选择「在本机播放」 | 页面在自己的设备上播放，账号、队列、曲库与遥控模式完全独立，外观设置共用。 |

遥控端可以在「设置 → 播放控制 → 播放位置」切换「控制服务器 / 本机播放」。选择「控制服务器」时需要输入 Host 的访问令牌。

## 服务与端口

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| 前端 | 3000 | 默认托管打包产物（`vite preview`），`--dev` 用开发模式 |
| 网易云 API | 4000 | 跑仓库里的 `scripts/start-netease-api.cjs`（与桌面版同一份代码和补丁）；设了 `API_DIR` 才改用外部的 api-enhanced 目录（旧办法） |
| Stage 中继 | 4100 | WebSocket + HTTP，转发遥控、代理各音乐 API、校验令牌 |
| QQ 音乐 API | 4300 | `scripts/start-qq-api.cjs` |
| 酷狗 API | 4400 | `scripts/start-kugou-api.cjs` |

前端的 `/stage`、`/ncm`、`/qq`、`/kugou` 路径由 Vite 反代到对应服务，对外只需要暴露 3000 一个端口。

## 一键启动

```bat
scripts\start-stage.cmd
```

- 默认只开**一个**黑框，五个服务的日志合在一起，行首带 `[API]` `[Relay]` `[QQ]` `[KuGou]` `[Web]` 前缀；**关掉这个窗口或按 Ctrl+C，全部一起停**。
- 启动前会先停掉上一次留下的同端口 **node** 进程，所以重启只需要再运行一次，不用手动关窗口。其他程序（例如占用相近端口的桌面版 QQ）不会被误杀。
- 前端先构建再监听 3000，构建期间稍等几秒。
- 脚本等前端就绪后，会用你的 Chrome 打开 Host 页（已带令牌），并附上防后台降级的参数。

可选参数：`--dev`（用开发服务器）、`--no-browser`（不自动打开 Host 页）、`--separate`（每个服务一个窗口，旧行为）、`--dry-run`（只打印不执行）。停止：`scripts\stop-stage.cmd`。

> 请在服务器的**控制台桌面**（RustDesk / ToDesk 等）上运行，不要用 RDP——RDP 会话的声音不会从服务器本机输出。
> Chrome 的防降级参数只在 Chrome 全新启动时生效；如果 Chrome 已在运行，请先关闭所有 Chrome 窗口再运行脚本，否则 Host 窗口在后台时音乐可能每秒卡顿。Host 页在窗口失焦时会停止绘制画面（点一下窗口恢复），这是为了避免卡顿，属于预期行为。

## 访问令牌

- 中继首次启动时随机生成令牌，保存到 `~/.folia-stage/token`；也可以用环境变量 `STAGE_TOKEN` 指定，或 `STAGE_TOKEN_FILE` 换文件位置。
- 启动脚本会在黑框里打印令牌，Host 页的「设置 → 播放控制 → 播放位置」里也能看到。
- **只有带 `?token=` 的地址才默认进入遥控模式**；手动选择遥控模式时需要填写令牌。
- 中继对所有遥控接口、Host 的 WebSocket、曲库访问和共享账号代理都校验令牌，并带有限流。没有令牌的访问者只能「本机播放」。
- 遥控端只放行点歌/遥控所需的路由，歌词注入、媒体上传、清状态等写入类路由一律 404。

## 账号共享

Host 上登录的网易云、QQ 音乐、酷狗账号，遥控端可以直接借用（中继在代理请求时注入账号，浏览器里只持有占位标记 `shared-with-stage-host:<令牌>`，真实 Cookie 不会下发到遥控端）。遥控端也可以切到「本机播放」使用自己的账号，两套账号互不影响。

## 跨平台混排队列

网易云、QQ 音乐、酷狗的歌可以放进**同一个**播放队列混着播放。切换在线平台**不会**清空当前播放与队列，也不再弹出确认框。遥控协议对三个平台一致。

## Spotify（网页版）

上游的 Spotify 只在桌面版里能用（要借 Electron 做登录回调和本地解密播放）。本 Fork 把桌面版的 Spotify 桥搬到了 Stage 中继里（`server/stage-relay/spotify.cjs`），所以网页版也能用，**账号和解密都在服务器上**。

**两种账号，互相独立**

| 页面 | 用哪个账号 | 谁能登录 / 登出 |
| --- | --- | --- |
| Host 页、遥控页（带令牌） | 服务器上**共用**的那一个，所有带令牌的访问者共用 | 只有 Host 页（和桌面版） |
| 本机播放的页面（不需要令牌） | **自己的一份**：浏览器里存一个随机的账号标识，服务器只存它的哈希，账号用它派生的密钥封存，只有这个浏览器能打开 | 这个浏览器自己 |

本机播放的页面和 Host / 遥控页的账号互不影响，和其他平台「本机模式账号独立」的规则一致。

**前提**
- 一个 Spotify **会员**账号（免费账号只能浏览，不能播放），音质最高 320k。
- 服务器上装了可选依赖 `@lox-audioserver/node-librespot`（`npm install` 会装；它是原生模块，Windows x64 有预编译包）。
- 部署配置了 Stage 中继（`VITE_STAGE_RELAY=1`）。

**登录**
- **在服务器上登录（Host 页）**：在服务器的桌面上（RustDesk 等）打开 Host 页，登录窗口选 Spotify，点「打开浏览器」，中继会在服务器自己的默认浏览器里打开授权页，点「同意」即可，授权页回调到服务器本机的 `127.0.0.1:5588`，自动完成。
- **在自己的设备上登录（本机播放的页面，手机也行）**：点「打开浏览器」，授权页在你自己的浏览器里打开。授权之后 Spotify 把浏览器送回 `http://127.0.0.1:5588/login?code=…`，这个地址只有服务器自己能接住，所以在手机或别的电脑上这个页面会**打不开**——这是正常的：把地址栏里的**完整网址复制下来**，粘贴到登录窗口下方的输入框，点「完成登录」，服务器就会接着完成登录。授权码很快失效，请在授权后马上粘贴。
- 同一时间只能有一个人在登录（服务器上只有一个 5588 端口）。
- 凭据保存在服务器的 `~/.folia-spotify`（可用环境变量 `SPOTIFY_STATE_DIR` 改位置）：共用账号放在该目录下、用密钥文件加密；本机播放的页面的账号放在 `profiles/` 下。

**数据流**
- 浏览、搜索、歌单、红心等请求：页面 → `POST /stage/spotify/api`（共用账号带访问令牌，自己的账号带账号标识）→ 中继里的桥 → Spotify。
- 播放：播放器请求 `/stage/spotify/audio/<歌曲id>?k=…&token=…`（或 `&profile=…`），中继用 librespot 以对应账号取得并解密音频后分段（支持 Range）回给播放器。遥控端点歌时，歌由 Host 播放，用共用账号。

**安全与限制**
- 本机播放的页面不需要访问令牌，所以**任何能访问中继的人都能在服务器上建一个自己的 Spotify 账号**。服务器上限 32 个账号、每分钟最多新建 6 个；不想开放就设环境变量 `SPOTIFY_LOCAL_PROFILES=0`，此时本机页用不了 Spotify。部署在公网时请把站点放在访问控制（如 Cloudflare Access）之后。
- 共用账号的访问者共用你的会员，令牌只给信任的人。
- librespot 直连 Spotify，**不走 HTTP 代理**；API 请求的代理原则与 AI 主题生成一致：每次实际探测，直连 Spotify 通就直连（TUN 或网络本身就通），不通才走代理（`AI_PROXY_URL` > `HTTPS_PROXY` > Windows 系统代理，且代理要在监听），都不通就直接报原因；探测结果缓存约 30 秒，开关代理后自动跟上。这只发生在服务器上，浏览器那端不受影响。如果你的网络只有「系统代理」没有 TUN / 全局直连，能浏览但播放会失败——开 TUN，或让服务器直连 Spotify。
- Spotify 可能随时改接口，导致浏览或播放失效；这是第三方实现，不受官方支持，也不符合 Spotify 的使用条款，仅限自用。
- 没有磁盘缓存（桌面版有）。服务器上如果 librespot 没装上，播放会报「Spotify playback is not available on this system」，先确认 `node_modules/@lox-audioserver/node-librespot` 存在。
- 登录失败或回调不到：确认服务器的 5588 端口没被别的程序占用；日志在中继的黑框里（`[Spotify] …`）。

## 播放模式同步

循环模式（关闭 / 列表 / 单曲 / 随机 / 心动）在遥控端与 Host 之间双向同步。「心动」只在 Host 正在播放网易云「我喜欢的音乐」时可用，是否可用由 Host 随状态一起告知遥控端，遥控端的循环按钮据此决定要不要切到心动。遥控端从「我喜欢的音乐」歌单页点播放时，会把歌单与这批歌的键交给 Host（控制动作 `set-heartbeat-context`），否则 Host 不知道这些歌来自哪个歌单。

## Host 本地曲库

遥控端可以浏览并播放 Host 上已关联的本地音乐文件夹。

## 跨平台歌单同步

跨平台歌单默认只存在各设备本机（见 [Fork 功能清单](fork-features.md#65-跨平台歌单)）。中继提供一组同步接口，让多台设备用「同步码」关联起来：

- 一台设备点「同步」→「生成同步码」（8 位，5 分钟内有效、只能用一次），另一台设备输入这个码，两边就在同一个**同步组**里，此后互相同步。
- 服务器把每个同步组的歌单放在 `~/.folia-stage/sync/<组 id>.json`（环境变量 `STAGE_SYNC_DIR` 可改位置）；只存组密钥的哈希。歌单是**明文**存的，请只在可信网络里使用。
- 接口在 `/stage/sync/*`：不需要访问令牌（只在本机播放的浏览器没有令牌），凭组密钥访问；有大小限制（单次 4 MB、每组 8 MB、最多 500 个组、每组 500 个歌单）；猜同步码会被限流（每分钟 15 次错误）。
- 合并规则：按歌单整份合并，修改时间较晚的那份为准；删除的歌单留一个标记，避免旧副本把它带回来。
- 网页版（由中继的页面提供）直接用页面自己的地址；桌面版没有被服务器托管，在同步窗口里填服务器地址（已填过「遥控服务器」时自动带出）。
- 服务端需要更新到支持同步的版本（`start-stage.cmd --auto-update` 会自动更新并重启）。

## 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `STAGE_PORT` | 4100 | 中继监听端口 |
| `LISTEN_HOST` | 0.0.0.0 | 中继监听地址 |
| `NETEASE_PORT` / `QQ_PORT` / `KUGOU_PORT` | 4000 / 4300 / 4400 | 中继代理的后端端口 |
| `STAGE_TOKEN` / `STAGE_TOKEN_FILE` | 自动生成 | 访问令牌来源 |
| `STAGE_SYNC_DIR` | `~/.folia-stage/sync` | 跨平台歌单同步组的存放目录 |
| `API_DIR` | （不设） | 不设就用仓库里的网易云 API；设成 api-enhanced 目录则改用它（旧办法） |

## 排错

- **遥控端点歌后没声音**：确认 Host 页在服务器控制台桌面上打开、没有被浏览器的自动播放策略拦住（点一下页面），且 Host 页令牌正确。
- **网易云只能试听 30 秒**：未登录的网易云账号只能试听，这是上游规则，在 Host 上登录账号即可。
- **启动后默认平台不对**：默认平台按 网易云 > QQ 音乐 > 酷狗 的顺序选第一个已登录的；账号状态稳定前不会抢先决定，稍等即可。
- **端口被占用**：先运行 `scripts\stop-stage.cmd`；只会结束 node 进程。
